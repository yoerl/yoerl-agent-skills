# Test Scenario Full (시나리오 1개 = 문서 1개, TC마다 10절)

사용자가 **기능·업무 흐름**에 대해 "시나리오 문서 안에 테스트 케이스까지 전부" 요청하면 이 스킬만 따른다.
흐름 이름은 자연어로 주어진다 (예: `장바구니 담기`, `회원 가입`, `주문 취소`).

**목표:** 흐름을 `TS-*` 단위로 쪼갠 뒤, **`TS-*`마다 마크다운 파일 1개**를 만든다. 그 파일 하나에 `TS-*`의 **모든 `TC-*`**가 들어가고, **TC 1개마다 10절**을 채운다. 실행·판정·결함 확정 없음(문서만).

이 스킬은 `test-scenario`·`test-case` 스킬 없이 **단독 설치해도 동작**한다. 필요한 규칙·양식은 모두 이 스킬 안에 있다.

## 핵심 규칙

| 규칙 | 내용 |
|------|------|
| **시나리오 1개 = 파일 1개** | 한 파일에 `TS-*` **1개만.** 시나리오가 여러 개면 파일도 여러 개. |
| **TC는 전부 같은 파일** | 그 시나리오의 `TC-*`를 **빠짐없이** 같은 파일에 쓴다. TC를 별도 파일로 나누거나 링크·"별도 문서 참조"로만 두지 않는다. |
| **TC = 10절** | TC 1개의 정보 칸은 아래 [10절](#tc-1개의-10절)을 **전부, 순서대로** 쓴다. 절을 빼거나 합치지 않는다. 해당 없으면 `해당 없음`. |
| **기준 SHA 맨 위** | 파일의 첫 줄에 `기준 SHA: \`{short-sha}\``를 쓴다. 근거로 읽은 코드의 커밋이다. |
| **구조 트리 ↔ 상세 일치** | 구조 트리의 `TC-*` 개수·ID·순서가 TC 상세 블록과 같다. |
| **하위 TS 금지** | `TS-*` 아래는 `TC-*`만 둔다. |
| `[확인 필요]` | 코드·기획·스펙으로 확정 못 한 항목은 문구 끝 또는 칸에 표시. 추측으로 채우거나 빼지 않는다. |
| 결함 미확정 | 실행 전 단계이므로 버그·결함을 **확정하지 않는다.** 의심은 `먼저 볼 케이스` 또는 `[확인 필요]`로만 남긴다. |
| 9절 비움 | 9절 `실제 결과 및 판정`의 칸은 **비운다.** 에이전트가 채우지 않는다. |
| 테스트 실행 안 함 | UI 클릭·API 호출·E2E·단위 테스트 **실행 금지.** 문서 작성만 한다. |
| agent-safety | 제품 코드·설정 값을 바꾸지 않는다. 문서만 쓴다. |
| 양식 SSOT | 골격은 [references/template.md](references/template.md), 작성 예시는 [references/example.md](references/example.md). |

## TC 1개의 10절

| 절 | 이름 | 내용 |
|----|------|------|
| 1 | 기본 식별 정보 | TC ID, 시나리오 원본 TS, 유형(`정상`·`예외`·`경계`), 우선순위(`P1`·`P2`·`P3`) |
| 2 | 사전 조건 | 권한(역할), 진입 상태, 데이터 상태 |
| 3 | 테스트 입력 데이터 | 필드: 값 (정상 값 \| 경계값 \| 경계값 초과 \| 무효 값). 입력이 없으면 `해당 없음` |
| 4 | 시퀀스 다이어그램 | Mermaid `sequenceDiagram`, `autonumber` 켬. 사용자 → 화면 → API → 저장소 → 응답 순 |
| 5 | 시퀀스 다이어그램 기준 흐름표 | 4절 화살표를 **한 행씩** 옮긴 표 (번호·발신·수신·메시지·확인할 상태). 4절의 설명 표이므로 4절에 없는 행을 넣지 않는다 |
| 6 | 검증 로직 | 관찰 지점별 **참·거짓 판정 가능한 검증 규칙** (V1, V2 …) + 판정 규칙 |
| 7 | 테스트 수행 절차 | 사용자가 하는 조작만 번호 목록. 호출 순서·내부 처리는 4·5절에만 쓰고 여기서 반복하지 않는다 |
| 8 | 예상 결과 | 6절 규칙을 모두 충족했을 때의 **최종 화면·데이터 스냅샷**. 6절 문장을 복사하지 않는다 |
| 9 | 실제 결과 및 판정 | **빈 칸.** 실제 결과·판정(Pass/Fail)은 실행하는 사람이 채움 |
| 10 | 참조 API | 4절에서 호출하는 엔드포인트: 메서드·경로·요청·성공 응답·근거 코드 위치. UI만이면 `해당 없음` |

**4·5절은 TC마다 필요하다.** 같은 내용을 두 번 쓰지 않는다: 4절이 원본, 5절은 그 설명 표, 7절은 사용자 조작 절차만.

## 파일명·경로

| 항목 | 규칙 |
|------|------|
| 경로 | `docs/test-case/` (플랫. `{타임스탬프}/{도메인}/` 하위 트리에 넣지 않음) |
| 파일명 | `{YYYYMMDD_HHMMSS}_{TS_SLUG}_SCENARIO_FULL.md` |
| 타임스탬프 | KST. 배치 작성 시 같은 타임스탬프를 여러 TS 파일에 재사용 가능 |
| `TS_SLUG` | `TS-FOOD-CART-001` → `FOOD_CART` 등 도메인·기능 식별용 `UPPER_SNAKE_CASE` (순번 제외 권장) |
| 덮어쓰기 | 기존 파일을 덮어쓰지 않는다. 다시 쓰면 새 타임스탬프 파일. |

`_SCENARIO_FULL.md` 접미사는 TC 상세를 포함하지 않는 `*_SCENARIO.md`(케이스 표만 있는 시나리오 문서)와 구분하려는 것이다.

## ID 규칙

- **시나리오:** `TS-{도메인}-{행위}-{순번}` (파일 1개 = `TS-*` 1개)
- **케이스:** `TC-{도메인}-{행위}-{순번}` (예: `TC-CART-ADD-001`)
- **중복 방지:** 작성 전 `docs/test-case/`에서 `TS-`·`TC-`를 grep해 ID가 겹치지 않게 한다.

## 실행 순서

### 1. 범위·TS 분해

- 흐름을 한 문장으로 정의한다 (시작 → 성공 종료).
- 포함·제외 화면·API·권한을 bullet로 보여 준다.
- 이번 요청에서 쓸 **`TS-*` 목록**을 만든다. TS마다 **파일 1개**가 생긴다.
- 범위가 크면 이번 세션에 쓸 TS만 선택하고 나머지는 `이번 범위에서 뺀 것`에 남긴다.

### 2. TS마다 TC 분해 (1:N)

- 각 `TS-*`에 대해 `TC-*`를 쪼갠다. 정상(해피)·예외·경계가 모두 있는지 본다.
- 권한·상태 분기가 있으면 합치지 말고 각각 독립 TC로 쓴다.
- TC마다 4절 호출 순서를 코드(화면 핸들러·API 라우트·저장 로직)에서 확인해 그린다. 추측으로 참여자를 만들지 않는다.
- 코드 근거(파일·줄)와 `기준 SHA`를 적는다.

### 3. TS당 파일 1개 작성

- 골격: [references/template.md](references/template.md) — 기준 SHA → 시나리오 정보 → 실행 전 준비 → 구조(트리) → 먼저 볼 케이스 → **TC마다 10절** → 근거 → 이번 범위에서 뺀 것 → 기존 문서와의 관계.
- TC 상세는 구조 트리 순서대로 **전 TC를** 쓴다. 일부만 쓰고 "나머지 생략"으로 끝내지 않는다.
- 연속 TS는 `앞 시나리오` / `이어지는 시나리오`로 파일명을 서로 적는다 (링크만 있는 것은 시나리오 간 연결에만 허용, TC 상세는 대체 불가).

### 4. 완료 전 점검 (파일마다)

- [ ] 파일 첫 줄에 `기준 SHA`가 있다
- [ ] 이 파일의 `TS-*`는 **1개만** (제목·트리 루트 1개)
- [ ] 트리 = TC 상세 블록의 `TC-*` (개수·ID·순서 일치)
- [ ] 모든 `TC-*`가 **이 파일 안에** 있다 (별도 파일·링크로 미룬 TC 없음)
- [ ] TC마다 10절이 **모두 있고 순서대로** 있다 (1 식별 · 2 사전 조건 · 3 입력 · 4 시퀀스 · 5 흐름표 · 6 검증 · 7 절차 · 8 예상 결과 · 9 실제 결과 · 10 참조 API)
- [ ] 4절 Mermaid의 화살표 수 = 5절 흐름표 행 수, 번호·메시지 문구 일치
- [ ] 7절이 4·5절 호출 순서를 반복하지 않는다 (사용자 조작만)
- [ ] 6절 규칙은 참·거짓으로 판정 가능하다
- [ ] 9절 `실제 결과`·`판정`이 **전부 비어 있다**
- [ ] 하위 `TS-*` 없음
- [ ] grep으로 `TS-`·`TC-` ID 중복 없음
- [ ] 테스트 실행·제품 코드 변경 없음
- [ ] 특정 비공개 프로젝트명·경로·계정·비밀값이 들어가지 않았다
- [ ] `[확인 필요]` 요약이 보고에 포함

## 하지 말 것

- 한 파일에 `TS-*` 2개 이상
- TC 상세를 별도 파일로 분리하거나 링크로만 남기기
- TC 10절 중 하나를 빼거나 다른 절과 합치기
- 구조 트리에만 있고 상세가 없는 TC (또는 그 반대)
- 5절에 4절 다이어그램에 없는 행 넣기, 7절에 호출 순서 반복하기
- Pass/Fail·결함 확정, 9절 칸 채우기
- 테스트 실행, 제품 코드·설정 변경
- `docs/test-case/{타임스탬프}/{도메인}/` 아래에 저장
- 기존 시나리오 파일 덮어쓰기
