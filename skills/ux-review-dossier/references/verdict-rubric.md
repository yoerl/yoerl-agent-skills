# UXD 판정 기준 (Verdict Rubric)

## 1. 최종 판정 4종

| 판정 | 의미 | 다음 |
|------|------|------|
| **통과** | Critical 0, Major 0~1 경미 — 진행 가능 | 기록만 |
| **보류** | Critical≥1 또는 Major 2+ — 수정·검증 선행 | 수정 → **재스캔** |
| **풀평가** | 범위·논쟁·영향 큼 — 5H로 부족 | `heuristic-evaluation` 10H |
| **조건부 통과** | Critical·Major 정리됨, **needs-test**만 남음 | QA 후 최종 통과 기록 |

## 2. 판정 결정 트리

```
Critical ≥ 1     → 보류
Major ≥ 2        → 보류
Major 1 + 애매   → 보류 또는 풀평가
Critical 0, Major 0~1 경미 → 통과
정책 미결·대형 출시 게이트    → 풀평가
needs-test만 잔류 + 수정 반영  → 조건부 통과
```

## 3. 심각도 (이슈 태그)

| 등급 | 정의 | 예 (리즈프로필) |
|------|------|----------------|
| **Critical** | 안전·사기·가입/결제 막힘·데이터 무결성 | 인증 후 번호 변경으로 검증 우회 |
| **Major** | 태스크 완료·복구 어려움 | OAuth 실패 피드백 부족 |
| **Minor** | 불편하나 우회 가능 | Step 라벨만 불명확 |

휴리스틱 # = 유형, 심각도 = 영향.

## 4. Quick Scan 5H — 보류 신호

| H | 보류 쉬운 신호 |
|---|----------------|
| #1 | 제출·결제 후 무응답, 성공/실패 불명 |
| #5 | 확인 없는 비가역 행동, 식별·인증 불일치 |
| #9 | 에러 코드만, 복구 방법 없음 |
| #6 | 필수 정보 숨김, 다단계에서 방향 상실 |
| #2 | 모르는 용어로 필수 단계 막힘 |

Minor만 → 통과 검토. Critical 하나 → **무조건 보류**.

## 5. §1 판정과 §4 HE 관계

| 상황 | §1 판정 |
|------|---------|
| quick-scan만 | §3 판정과 동일 |
| 풀 HE 완료, Critical 0 | 통과 |
| 풀 HE 후 Critical/Major 잔류 | 보류 |
| needs-test만 잔류 | 조건부 통과 |

## 6. evidence-brief(§5)와 판정

- 정책·옵션 미결 → **보류** 또는 **풀평가**
- §5 권고 확정 + handoff(§6) 후 재스캔 → **통과** 가능

## 7. 기록 규칙

- 판정 변경 시 **날짜·사유** 1줄 (같은 파일 하단 또는 새 UXD 파일).
- 재평가: `{task-slug}-{새날짜}.md` 신규 파일 (이력 유지).
